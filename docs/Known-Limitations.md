# Known limitations — v1.0.0

- **No Windows runtime execution here.** WPF layout/bindings, UAC/token/pipe/NTFS behavior, Windows providers, localized native command output, WUA, real installers and the standard Windows MSBuild route must be accepted on Windows. Cross compilation is not proof of these behaviors.
- Unsigned build; endpoint controls can block it. Framework 4.8-compatible Windows x64 desktop is required. EXE.config must remain next to the EXE. Elevation/staging requires local NTFS and rejects reparse locations.
- **Adobe:** direct resolution requires an eligible standalone x64 English Reader link in Adobe's official distribution page. Dynamically gated/changed pages can fail resolution. No guessed version URL, bundled Adobe installer, or automatic fallback is used. Use the official Adobe page/authorized distribution route or explicitly choose WinGet. Redistribution rights are not assumed.
- **Ookla:** official primary CLI/terms pages could not be retrieved in this environment and no enterprise or redistribution permission was established. Browser handoff is implemented; native test execution, JSON capture, native test history/comparison are intentionally not exposed. No claim is made that opening the browser licenses commercial use; review provider terms. No bandwidth test starts automatically.
- Vendor metadata/CDNs/publishers can change. Allowlist mismatches, rate limiting, absent assets/digests, certificate revocation failures or invalid signatures fail closed. Direct providers were implemented but live downloads and installations were not executed here. Silent arguments are profile-specific; all must pass Windows acceptance. PowerToys may install vendor-managed prerequisites.
- Direct scopes: VS Code current user, all other catalog entries machine-wide. Adobe uses the standalone English profile. Java choices remain explicit JRE/JDK and LTS 17/21. No arbitrary package/version/path input reaches the helper.
- Available versions from stable endpoints may remain Unknown until post-install evidence is collected. Success requires a recognized registry identity/publisher, readable version and known-release version match where supplied. This is not application launch/license validation. Updates with unchanged versions are inconclusive. Reboot codes remain distinct. Ambiguous unified Adobe Acrobat entries are not treated as verified Reader. Registry inventory does not cover every Store/MSIX or portable app; registry view is not asserted to be executable architecture.
- Local GPUpdate is intentionally interactive: current-process context, fixed cmd /k command, no automated verification, redirected streams or helper elevation. Only window launch is reported; the technician handles Windows prompts. Remote GPUpdate retains authorized RSAT/current credentials and bounded event evidence; scheduled is not applied.
- Servicing and running installers are not killed on Cancel. Download cancellation crosses the authenticated pipe, but UAC/network provider responses may delay it. UI monitoring has an eight-hour bound; after that the provider may still be running and duplicate work is blocked/guarded. Child process trees are not forcibly terminated; launcher PID and inherited-output completion are tracked, not every service-hosted descendant.
- WMI/WUA timeout means observation ended, not that a native call was aborted. Outstanding calls remain guarded to avoid replacement floods. Windows Update scan is opt-in, policy-controlled, read-only; it can outlive the 180-second observation deadline. No scan means no claim of fully updated.
- Storage/SMART/BitLocker providers differ by drive/controller/permissions. Missing or denied data is not Healthy. Device problem filtering applies to PnP entries; the full driver inventory remains visible. CPU is a one-second sample, not a continuous profiler; inaccessible process details are omitted. Startup inventory uses Win32_StartupCommand and may omit task/service-based autostarts.
- The advanced overview summarizes active adapters; targeted tests and snapshot tools retain selected-adapter operations. Internet tests use the entered target and TCP/HTTPS 443; they are not proof of general internet reachability. Snapshot save/load is explicit and unredacted. CSV/JSON software export reflects the filtered table. Category entry automatically performs bounded read-only collection; update availability scans and bandwidth tests remain explicit.
- Privacy report redaction masks known identities, sensitive fields, address/path patterns and omits sensitive operation/event fields by default. No secret stores/product keys are queried. Redaction cannot guarantee detection of arbitrary sensitive text; review exports. Explicit raw text/inventory exports are not anonymized. Output/log buffers are bounded and may truncate; overflow is reported.
- Same-user compromise, administrator compromise and replacement of the complete unsigned application before launch are outside the portable application's trust boundary. No security policy is weakened.

- NetFx3 non-elevated skip uses Win32_OptionalFeature only when pending-reboot indicators are clear. Pending/unknown/restricted evidence requires an elevated DISM read-only feature query before any enablement; unknown blocks mutation. This may request UAC solely to obtain authoritative state when standard-user data is insufficient.
- Unknown latest vendor versions remain Unknown. Stable endpoints for several vendors do not supply a trusted dynamic version in this implementation; explicit Update can run, but unchanged installed versions are inconclusive. Adobe page discovery remains conditional on its published distribution page.
- DNS flush and SFC do not have a universal independent postcondition in this release; their native output and before/after evidence are retained, but a zero code does not become SuccessfullyChanged. DHCP renew with an unchanged address and no independent lease-time proof is also inconclusive.
- Current-user Windows Update Settings handoff cannot observe/verify subsequent user actions in Settings; no installation success is asserted. Remote policy event access can be blocked independently of remote scheduling.

- Category cache is session-local and lasts two minutes; manual Refresh bypasses it. Ordinary hardware values are not health certification. NVMe is a bus type; unavailable media data is not guessed as SSD. Storage provider failure, absent SMART/reliability counters and restricted BitLocker access remain explicit.
- Service control excludes a fixed core/security protection list in addition to Windows permissions. This is not a complete safety classification of every third-party service; explicit confirmation and authorized technician judgment remain necessary. Service restart is a real stop/start and may interrupt applications.
- Event browsing loads at most 500 records per page from one selected log. Source filtering is an exact provider name; time range is 1–30 days. A selected event is reread for full details and may have rolled out of the log. Security access is not silently elevated. Event messages and explicit technical details can contain sensitive information.
- Lenovo/Dell direct utility availability is conditional on official HTML metadata, unambiguous product/Windows 11 x64 identity, allowed HTTPS origins and Windows publisher verification. JavaScript-gated/changed pages may require the explicit official-page fallback. This fallback is not a download. These new downloads, publisher trust, native Downloads-folder resolution and Explorer selection were not executed on Windows here. Model-specific compatibility remains a manual vendor check before installation.
- Lenovo's published notice states maintenance ended 31 October 2026 and EOL is 31 March 2027. The action surfaces this notice and stops automatic direct resolution at EOL. No different Lenovo product is silently substituted. Dell Universal/ARM/SupportAssist is not substituted for Classic x64.

- Public v1.0.0 startup/config/helper rename, native icon/taskbar display and COM shortcut creation need real Windows acceptance. Hidden config is stored in ZIP attributes but not every extractor preserves it. The config remains mandatory even when hidden.
- Selected-app uninstall supports eligible registry-registered MSI/EXE software only, not Store/MSIX/portable packages or arbitrary shell commands. Ambiguous command lines, unsigned EXEs, machine EXEs outside protected Program Files or unusual ownership/ACLs are refused. Microsoft/system/runtime/security components are conservatively protected. This can block legitimate apps; use Windows Installed apps or the vendor's authorized process, not weakened validation.
- A vendor uninstaller may fork, prompt, require restart or leave data/registration behind. Postcheck polls boundedly for registration disappearance; if a child is still active, the result is inconclusive. No claim is made that every leftover file was deleted. Cross-instance duplicate protection is per initiating user; Windows Installer also enforces its own execution rules.
- Notepad++ failure analysis identifies the old EXE-only dual-signature selection path; the exact user exception was not supplied/reproduced. The official x64 MSI/hash profile avoids that signature-selection ambiguity, but actual download, Windows trust, installation and postcheck must be tested. No self-signed root is imported and no legacy unsigned fallback is enabled.
- Actual Windows screenshots were not captured; README branding is original artwork, not a GUI acceptance screenshot. Use the capture checklist in Windows-Validation.md.

- Inconclusive uninstaller completion retains a per-app pending marker to refuse duplicate launches, including after the toolkit is reopened. Recovery requires independently confirming the vendor operation ended; follow Uninstall.md. This guard favors avoiding duplicate removal over blind automatic retry.
